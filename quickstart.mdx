This guide will help you install Patrol and run your first test. By the end, you'll have Patrol configured and a working test running on an emulator or device.

<Note>
If you want to use Patrol finders in your existing widget or golden tests, see [Using Patrol finders in widget tests](/finders/setup).
</Note>

## Prerequisites

Before you begin, make sure you have:

- Flutter SDK 3.32.0 or higher
- Dart SDK 3.8.0 or higher
- An Android emulator or iOS simulator (or physical device)
- Xcode (for iOS/macOS testing) or Android Studio (for Android testing)

## Installation

<Steps>
  <Step title="Install patrol_cli">
    The Patrol CLI is required to run integration tests. Install it globally:

    ```bash
    flutter pub global activate patrol_cli
    ```

    <Tip>
    Make sure to add the Dart pub cache to your `PATH` environment variable:
    
    **macOS/Linux:**
    ```bash
    export PATH="$PATH":"$HOME/.pub-cache/bin"
    ```
    
    **Windows:**
    ```powershell
    $env:PATH += ";$env:LOCALAPPDATA\Pub\Cache\bin"
    ```
    </Tip>

    Verify the installation:

    ```bash
    patrol --version
    ```
  </Step>

  <Step title="Check your environment">
    Run `patrol doctor` to verify your environment is set up correctly:

    ```bash
    patrol doctor
    ```

    Example output:
    ```
    Patrol CLI version: 4.1.0
    Android:
    • Program adb found in /Users/username/Library/Android/sdk/platform-tools/adb
    • Env var $ANDROID_HOME set to /Users/username/Library/Android/sdk
    iOS / macOS:
    • Program xcodebuild found in /usr/bin/xcodebuild
    • Program ideviceinstaller found in /opt/homebrew/bin/ideviceinstaller
    ```

    Make sure all checks are green for the platform you want to test.

    <Warning>
    **Using Flutter version managers?** 
    
    If you use FVM, puro, or another version manager, set the `PATROL_FLUTTER_COMMAND` environment variable:
    
    ```bash
    export PATROL_FLUTTER_COMMAND="fvm flutter"
    # or
    export PATROL_FLUTTER_COMMAND="puro flutter"
    ```
    
    Or pass it as an argument: `patrol test --flutter-command "fvm flutter"`
    </Warning>
  </Step>

  <Step title="Add Patrol to your project">
    Add `patrol` as a dev dependency:

    ```bash
    flutter pub add patrol --dev
    ```

    This adds the following to your `pubspec.yaml`:

    ```yaml pubspec.yaml
    dev_dependencies:
      patrol: ^4.1.1
      flutter_test:
        sdk: flutter
    ```
  </Step>

  <Step title="Configure patrol in pubspec.yaml">
    Add a `patrol` section to your `pubspec.yaml` with your app details:

    ```yaml pubspec.yaml
    name: my_app
    description: My awesome Flutter app

    dependencies:
      flutter:
        sdk: flutter

    dev_dependencies:
      patrol: ^4.1.1
      flutter_test:
        sdk: flutter

    patrol:
      app_name: My App
      android:
        package_name: com.example.myapp
      ios:
        bundle_id: com.example.MyApp
    ```

    <Accordion title="Where do I find package_name and bundle_id?">
      **Android package name:**
      - Open `android/app/build.gradle`
      - Look for `applicationId` in the `defaultConfig` section
      
      **iOS bundle ID:**
      - Open `ios/Runner.xcodeproj/project.pbxproj`
      - Search for `PRODUCT_BUNDLE_IDENTIFIER`
      - Or open your project in Xcode and check the General tab
    </Accordion>

    <Info>
    By default, Patrol looks for tests in `patrol_test/`. To use a different directory, add:
    
    ```yaml pubspec.yaml
    patrol:
      app_name: My App
      test_directory: integration_test  # Custom directory
      android:
        package_name: com.example.myapp
      ios:
        bundle_id: com.example.MyApp
    ```
    </Info>
  </Step>

  <Step title="Set up native integration">
    Patrol needs to integrate with your app's native code to enable full testing capabilities.

    <Tabs>
      <Tab title="Android">
        <Steps>
          <Step>
            Create the directory structure:
            ```bash
            mkdir -p android/app/src/androidTest/java/com/example/myapp
            ```
            
            <Warning>Replace `com/example/myapp` with your app's package name (use `/` instead of `.`)</Warning>
          </Step>

          <Step>
            Create `MainActivityTest.java` in that directory:

            ```java android/app/src/androidTest/java/com/example/myapp/MainActivityTest.java
            package com.example.myapp; // replace with your package name

            import androidx.test.platform.app.InstrumentationRegistry;
            import org.junit.Test;
            import org.junit.runner.RunWith;
            import org.junit.runners.Parameterized;
            import org.junit.runners.Parameterized.Parameters;
            import pl.leancode.patrol.PatrolJUnitRunner;

            @RunWith(Parameterized.class)
            public class MainActivityTest {
                @Parameters(name = "{0}")
                public static Object[] testCases() {
                    PatrolJUnitRunner instrumentation = (PatrolJUnitRunner) InstrumentationRegistry.getInstrumentation();
                    instrumentation.setUp(MainActivity.class);
                    instrumentation.waitForPatrolAppService();
                    return instrumentation.listDartTests();
                }

                public MainActivityTest(String dartTestName) {
                    this.dartTestName = dartTestName;
                }

                private final String dartTestName;

                @Test
                public void runDartTest() {
                    PatrolJUnitRunner instrumentation = (PatrolJUnitRunner) InstrumentationRegistry.getInstrumentation();
                    instrumentation.runDartTest(dartTestName);
                }
            }
            ```
          </Step>

          <Step>
            Update `android/app/build.gradle.kts` (or `build.gradle` if using Groovy):

            ```kotlin android/app/build.gradle.kts
            android {
                defaultConfig {
                    // Add these lines:
                    testInstrumentationRunner = "pl.leancode.patrol.PatrolJUnitRunner"
                    testInstrumentationRunnerArguments["clearPackageData"] = "true"
                }

                // Add this section:
                testOptions {
                    execution = "ANDROIDX_TEST_ORCHESTRATOR"
                }
            }

            dependencies {
                // Add this line:
                androidTestUtil("androidx.test:orchestrator:1.5.1")
            }
            ```
          </Step>
        </Steps>
      </Tab>

      <Tab title="iOS">
        <Steps>
          <Step>
            Open `ios/Runner.xcworkspace` in Xcode
          </Step>

          <Step>
            Create a UI testing target:
            - Select **File → New → Target**
            - Choose **UI Testing Bundle**
            - Set **Product Name** to `RunnerUITests`
            - Set **Organization Identifier** to match your app's bundle ID
            - Set **Target to be Tested** to `Runner`
            - Set **Language** to `Objective-C`
            - Click **Finish**
          </Step>

          <Step>
            Delete `RunnerUITestsLaunchTests.m` through Xcode (select it and choose **Move to Trash**)
          </Step>

          <Step>
            Replace the contents of `RunnerUITests.m`:

            ```objective-c ios/RunnerUITests/RunnerUITests.m
            @import XCTest;
            @import patrol;
            @import ObjectiveC.runtime;

            PATROL_INTEGRATION_TEST_IOS_RUNNER(RunnerUITests)
            ```
          </Step>

          <Step>
            Update `ios/Podfile` to include the new target:

            ```ruby ios/Podfile
            target 'Runner' do
              # Existing configuration...

              target 'RunnerUITests' do
                inherit! :complete
              end
            end
            ```
          </Step>

          <Step>
            Install pods:
            ```bash
            cd ios
            pod install --repo-update
            cd ..
            ```
          </Step>

          <Step>
            In Xcode, go to **RunnerUITests → Build Phases** and add two "Run Script Phase" build phases:
            - Name them `xcode_backend build` and `xcode_backend embed_and_thin`
            - Add this to `xcode_backend build`:
              ```bash
              /bin/sh "$FLUTTER_ROOT/packages/flutter_tools/bin/xcode_backend.sh" build
              ```
            - Add this to `xcode_backend embed_and_thin`:
              ```bash
              /bin/sh "$FLUTTER_ROOT/packages/flutter_tools/bin/xcode_backend.sh" embed_and_thin
              ```
          </Step>

          <Step>
            Disable parallel execution:
            - Go to **Product → Scheme → Edit Scheme**
            - Select **Test** from the left sidebar
            - Uncheck **Execute in parallel**
          </Step>

          <Step>
            Set **User Script Sandboxing** to **No**:
            - Select **RunnerUITests** target
            - Go to **Build Settings**
            - Search for "User Script Sandboxing"
            - Set to **No**
          </Step>
        </Steps>
      </Tab>
    </Tabs>
  </Step>

  <Step title="Create your first test">
    Create a test file at `patrol_test/example_test.dart`:

    ```dart patrol_test/example_test.dart
    import 'dart:io';

    import 'package:flutter/material.dart';
    import 'package:flutter_test/flutter_test.dart';
    import 'package:patrol/patrol.dart';

    void main() {
      patrolTest(
        'counter increments smoke test',
        ($) async {
          // Start the app
          await $.pumpWidgetAndSettle(
            MaterialApp(
              home: Scaffold(
                appBar: AppBar(title: const Text('Patrol Test')),
                body: Center(
                  child: Column(
                    mainAxisAlignment: MainAxisAlignment.center,
                    children: [
                      const Text('You have pushed the button this many times:'),
                      const Text('0', key: Key('counter')),
                      ElevatedButton(
                        key: const Key('increment'),
                        onPressed: () {},
                        child: const Text('Increment'),
                      ),
                    ],
                  ),
                ),
              ),
            ),
          );

          // Verify the app started
          expect($('Patrol Test'), findsOneWidget);
          
          // Test native interaction (except on macOS)
          if (!Platform.isMacOS) {
            await $.platform.mobile.pressHome();
          }
        },
      );
    }
    ```

    <Note>
    This is a simple test to verify Patrol is working. In real tests, you'd pump your actual app widget.
    </Note>
  </Step>

  <Step title="Run your first test">
    Make sure you have an emulator/simulator running or a device connected, then run:

    ```bash
    patrol test -t patrol_test/example_test.dart
    ```

    If everything is set up correctly, you should see output like:

    ```
    Test summary:
    📝 Total: 1
    ✅ Successful: 1
    ❌ Failed: 0
    ⏩ Skipped: 0
    📊 Report: build/patrol_test/reports/example_test.json
    ⏱️  Duration: 5s
    ```

    <Tip>
    **Developing tests faster with Hot Restart:**
    
    Use `patrol develop` instead of `patrol test` to enable hot restart:
    
    ```bash
    patrol develop -t patrol_test/example_test.dart
    ```
    
    Press `r` in the terminal to restart the test without rebuilding the app!
    </Tip>
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Test bundle error or version mismatch">
    This usually means your `patrol` and `patrol_cli` versions are incompatible.
    
    Check the [compatibility table](/compatibility) and ensure you're using compatible versions.
    
    ```bash
    # Check versions
    patrol --version
    flutter pub deps | grep patrol
    
    # Update to latest
    flutter pub global activate patrol_cli
    flutter pub upgrade patrol
    ```
  </Accordion>

  <Accordion title="Android: Unsupported class file major version">
    This is caused by using an incompatible JDK version. Patrol officially supports JDK 17.
    
    Check your JDK version:
    ```bash
    javac -version
    ```
    
    In Android Studio/IntelliJ, go to **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK** and select JDK 17.
  </Accordion>

  <Accordion title="iOS: Simulator gets cloned when running tests">
    This happens when parallel execution is enabled in Xcode.
    
    To fix:
    1. Open your project in Xcode
    2. Go to **Product → Scheme → Edit Scheme**
    3. Select **Test** from the left sidebar
    4. Uncheck **Execute in parallel**
    5. Repeat for all schemes if you have multiple
  </Accordion>

  <Accordion title="iOS: Wait for [app] to idle">
    This is usually caused by leftover `FLUTTER_TARGET` configuration.
    
    Search for `FLUTTER_TARGET` in your `*.xcconfig` and `*.pbxproj` files and remove both the key and value.
    
    Then regenerate the configuration:
    ```bash
    flutter build ios --config-only patrol_test/example_test.dart
    ```
  </Accordion>

  <Accordion title="Can't pump my app in tests">
    Make sure you're NOT calling:
    - `WidgetsFlutterBinding.ensureInitialized()` - Patrol handles this
    - `runApp()` - Use `$.pumpWidgetAndSettle()` instead
    - Modifying `FlutterError.onError` - This breaks test error handling
    
    See [Initializing app inside a test](#initializing-your-app-in-tests) below.
  </Accordion>
</AccordionGroup>

## Initializing Your App in Tests

To test your real app, you need to initialize it properly inside the test. Here are the key rules:

<Warning>
**DO NOT** in your test initialization:

1. Call `WidgetsFlutterBinding.ensureInitialized()` - Patrol already does this
2. Use `runApp()` - Use `$.pumpWidgetAndSettle()` instead
3. Modify `FlutterError.onError` - This breaks test error handling (e.g., Firebase Crashlytics)
</Warning>

**Good example:**

```dart patrol_test/app_test.dart
import 'package:my_app/main.dart';
import 'package:patrol/patrol.dart';

void main() {
  patrolTest('app test', ($) async {
    // Do your initialization
    await initializeServices();
    await loadConfig();
    
    // Pump your app (NOT runApp!)
    await $.pumpWidgetAndSettle(const MyApp());
    
    // Start testing
    await $('Login').tap();
  });
}

Future<void> initializeServices() async {
  // Initialize services, DI, etc.
  // But DON'T call WidgetsFlutterBinding.ensureInitialized()
}
```

<Tip>
Create a helper function for test initialization to avoid duplication:

```dart patrol_test/common.dart
import 'package:my_app/main.dart';
import 'package:patrol/patrol.dart';

Future<void> createApp(PatrolIntegrationTester $) async {
  await initializeServices();
  await $.pumpWidgetAndSettle(const MyApp());
}
```

Then use it in tests:
```dart
patrolTest('test', ($) async {
  await createApp($);
  // Continue testing...
});
```
</Tip>

## Using Flavors

If your app uses flavors, specify them in `pubspec.yaml`:

```yaml pubspec.yaml
patrol:
  app_name: My App
  flavor: development
  android:
    package_name: com.example.myapp.dev
  ios:
    bundle_id: com.example.MyApp.dev
```

Or pass as an argument:
```bash
patrol test --flavor development
```
